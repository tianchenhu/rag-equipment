# 设备维保知识库问答（RAG 练手）

用 22 篇模拟的设备维保文档，跑了一条最基础的 RAG 链路，对比五档切块大小对检索效果的影响。25 条测试问题上 Hit@3 跑到 0.96，最后定在 300 字一块。150 到 300 这三档命中率一样，300 的块数少了将近一半。
这是个练手项目。手头没有真实工单，文档是用脚本造的，工单、SOP、安全规范三类混在一起。有了这批文档，才把那条链跑通：切块、编码、余弦检索、拼 prompt、本地模型生成。
跑通之后，第一个想弄明白的是切块大小。网上一般说 512。我们这种文档一篇只有三四百字，512 砍下去跟没切差不多，所以干脆扫了五档，从 150 到 600，看看到底差多少，下面那张表就是这么来的。
代码是 AI 辅助写的。我负责跑通、读懂每一步在干什么、改参数做对照，看结果。

## 怎么跑

需要本地装了 ollama 并且拉了 qwen2.5:7b。

```bash
pip install -r requirements.txt

python rag.py                    # 建索引：22 篇 → 44 块 → 768 维
python rag.py ask "空压机排气温度高怎么办"
python eval.py                   # 跑评测
python eval.py --sweep           # 切块大小对照
python eval.py --refuse          # 拒答测试
```

第一次跑会下载 text2vec-base-chinese，400M 左右。

## 结果

25 条测试问题，chunk=300 / overlap=50 / top_k=3，索引 44 块：

| Hit@1 | Hit@3 | Hit@5 | Hit@10 | MRR |
|---|---|---|---|---|
| 0.880 | 0.960 | 0.960 | 1.000 | 0.927 |

按问法分一下：直接问的 12 条全中，换了说法的 8 条里错 1 条，需要跨文档拼的 5 条全中。

## 切块大小的对照

只改 chunk size，overlap 和 top_k 都不动：

| size | 块数 | Hit@1 | Hit@3 | MRR |
|---|---|---|---|---|
| 150 | 81 | 0.880 | 0.960 | 0.925 |
| 200 | 58 | 0.880 | 0.960 | 0.926 |
| **300** | **44** | 0.880 | **0.960** | **0.927** |
| 400 | 25 | 0.800 | 0.880 | 0.857 |
| 600 | 22 | 0.760 | 0.840 | 0.825 |

150、200、300 三档的 Hit@3 都是 0.960，一模一样，但块数从 81 掉到 44。也就是说切得再细一点用都没有，纯属白占地方。

400 之后开始掉，600 掉到 0.840。原因是块太大，一段里混了一堆不相关的内容，向量被平均掉了，方向就模糊。

所以最后选 300。不是因为它分数最高，它和 150 是打平的；是因为分数一样的前提下它块数最少。

顺带说一句，`eval.py --sweep` 会打印「最优：size=150」，那是直接按数值取最大值。实际选型得看成本，所以是 300。

## 拒答

另外造了 5 个资料里根本没有答案的问题，比如「去年设备维修总费用是多少」。prompt 第一句就写死：资料里没有就说未提及。5 条全拒了，没有瞎编参数。

工业场景里这条其实比命中率重要。答不出来顶多再查一次，答错一个参数可能就要出事。

## 错的那一条

Q13：「机床干久了尺寸越做越小，停一会儿又正常，是什么毛病？」

期望召回 WO-1057，实际召回 WO-1115、WO-1152、WO-1042。

这条挺好理解：问题问的是现象，文档写的是机理（主轴热变形、温升补偿）。两个说法在向量空间里离得远，「尺寸越做越小」和「热变形」字面上完全不像。

纯向量召回解决不了这类，得先把现象翻译成术语再检索，或者加一路 BM25 做混合检索。

## 几个已知问题

**指标偏乐观。** 22 篇平均 370 字，切完一篇就 2 块，基本等于从 22 篇里挑一篇，当然容易。这也是为什么 150/200/300 三档数字完全一样。换成几百页的手册肯定要掉，主要掉在跨章节那种问题上。所以 0.96 别当成真实水平看。

**同一篇的多个块会挤占 top-k。** 跑 walkthrough 能看到，正确答案排第 1，同一篇的第 2 块排第 4，等于 top_k 实际只有 2。按 doc_id 去重能解决，还没改。

**语料是造的。** 结构照着真实知识库来的，内容是编的，所以真实工单那种脏、长、互相引用的麻烦，这里没有。
